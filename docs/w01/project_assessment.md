## 1. 业务问题与诉求拆解

青禾优选是连锁零售企业，约 400 家门店，同时经营线上商城和小程序（`02_公司与项目协作关系.md` 第 3 段）。沈总在立项邮件和访谈中表达的诉求，可拆成四层：

- **结果期望**：复购率停止下滑并回升（MSG-04015）。具体提升幅度和计算口径尚未确定（MSG-04017），因此“止跌回升”目前是方向，不是可验收的指标。
- **时间期望**：三个月看到效果是沈总的期望；董事会是否有更硬的期限，他明确表示不能确认，不能当成已定要求（MSG-04015、MSG-04038）。
- **做法设想**：从约 80 万活跃会员中识别需要重点经营的人，把建议直接给到会员运营经理小林，避免另做一套表（邮件正文第 2 段）。当前已在做哪些应对动作，沈总表示“小林更清楚”，不能替运营确认（MSG-04017）。
- **原因假设**：“会员老化比较明显”需要小林、老周用数据核实（MSG-04015、MSG-04032）；上个智能营销项目失败，沈总归因于供应商，但具体环节、技术问题和当时使用情况“给不出可确认的细节，得看实际记录”（MSG-04028）。

推进条件也已澄清一部分：业务目标由沈总定；预算和合同要王经理参与，预算金额、审批流程、最终签字人和时长他都不掌握（MSG-04019、MSG-04024）。签约前他希望先谈清目标、数据口径和可做范围，“不会要求你们先无偿投入”（MSG-04019）。

## 3. 适配判断

总体判断不变：**分析型能力在样例上已验证可复用；客户数据接入、指标语义、运营动作和效果验收仍需适配。样例跑通不等于青禾已适配。** 访谈没有推翻任何分类，但把“下一步找谁”具体化了。

- **产品已有（GAP-003、GAP-004）**：下降会员识别、金额与订单依据、逐会员建议都有实现和运行证据。但“重点经营”的定义、80 万口径、建议在小林工作流中的可用性仍未验证。
- **系统适配（GAP-006）**：需要接入会员、订单、门店数据。沈总把系统条件指向老周，本人不掌握字段、覆盖或访问条件。
- **产品缺口（GAP-001）**：标准语义只覆盖净消费、老会员和下降阈值，没有“复购率”指标；是否新增取决于小林确认的口径。
- **暂不承诺（GAP-005）**：三个月已被澄清为期望，提升幅度和验收方式仍未定，本周不作时间或效果承诺。
- **待判断（GAP-002）**：会员老化只是原因假设，缺少数据验证；需先与老周、小林确认用什么口径和分析方法。

逐项能力 ID、证据状态和下一步见 `artifacts/w01/product_fit_gap.json`（GAP-001～006），此处不重复表格。

## 5. 下一阶段建议及承诺边界

**建议：带条件继续**，进入“需求澄清 + 只读数据验证”阶段，不直接进入实施。

开始前提：

1. 沈总确认本期优先解决的一个业务问题，并把“止跌回升”转成可验收指标；
2. 小林提供复购率口径、近四季度数据和当前运营动作；
3. 老周提供只读数据样本、字段说明与访问条件；
4. 王经理确认预算、审批流程与签约前双方可承担的范围；
5. 如本期涉及门店执行，陈姐确认门店是否能承接后续触达。

投入范围：需求澄清、数据抽样核验、客户语义与样例能力的映射验证。不包含生产接入、标签/发券上线和效果承诺。

**不承诺**：三个月见效、具体提升幅度、完整功能交付、生产环境标签或发券接入。沈总所说“签约前不会要求无偿投入”目前是他的表述；签约前具体做什么、做到什么程度，仍需双方书面确认。

**调整或暂缓条件**：数据无法取得或质量不足、复购率口径无法统一、预算/范围未确认，或只读验证发现关键能力缺口时，暂缓实施并回到澄清。
